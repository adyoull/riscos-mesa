Overview

    RISC OS is a cooperatively multitasking operating system. On its
    desktop, applications ("tasks") own windows handled by the Window
    Manager (the "Wimp"). A task receives events by calling Wimp_Poll, and
    must redraw its windows when asked, through the Wimp_RedrawWindow /
    Wimp_GetRectangle loop; nothing is drawn into a window at any other
    time without Wimp_UpdateWindow. Full-screen programs instead own the
    whole screen.

    This extension defines the RISC OS native window and pixmap types for
    EGL, surfaces placed inside a window's scrollable work area, the use of
    the whole screen, and two functions that let a task, which owns its
    event loop, redraw its EGL surfaces when the Wimp asks.

New Tokens

    Accepted as the <native_window> argument of eglCreateWindowSurface
    (the value, cast to EGLNativeWindowType):

        EGL_RISCOS_SCREEN_WINDOW                ((EGLNativeWindowType) -1)

    Accepted as attributes in the <attrib_list> of eglCreateWindowSurface
    and eglCreatePlatformWindowSurface(EXT):

        EGL_WORK_AREA_X_RISCOS                  0x35A0
        EGL_WORK_AREA_Y_RISCOS                  0x35A1
        EGL_WORK_AREA_WIDTH_RISCOS              0x35A2
        EGL_WORK_AREA_HEIGHT_RISCOS             0x35A3

    Accepted as an attribute in the <attrib_list> of
    eglCreateWindowSurface and eglCreatePlatformWindowSurface(EXT), and as
    the <attribute> argument of eglQuerySurface:

        EGL_SCREEN_BANKS_RISCOS                 0x35A4

    Returned as the EGL_NATIVE_VISUAL_ID of a config (these are the colour
    order bits of the RISC OS ModeFlags mode variable, not EGL enums):

        EGL_RISCOS_VISUAL_TBGR                  0x0000
        EGL_RISCOS_VISUAL_TRGB                  0x4000

Native types

    On RISC OS (compilers define __riscos__), eglplatform.h defines:

        typedef int   EGLNativeDisplayType;  /* EGL_DEFAULT_DISPLAY only */
        typedef void *EGLNativePixmapType;   /* a sprite */
        typedef int   EGLNativeWindowType;   /* a Wimp window handle */

    A native pixmap is a pointer to the header of a sprite with 32 bits per
    pixel, in any sprite area. Rendering goes straight into the sprite's
    image, whose first row is the top of the image. The config used must
    have the sprite's colour order as its EGL_NATIVE_VISUAL_ID (0x00BBGGRR
    for EGL_RISCOS_VISUAL_TBGR, 0x00RRGGBB for EGL_RISCOS_VISUAL_TRGB).

    A native window is the handle of a Wimp window owned by the calling
    task, or EGL_RISCOS_SCREEN_WINDOW for the whole screen.

Additions to Chapter 3 of the EGL 1.5 Specification (EGL Functions and
Errors)

    Add to section 3.5.1 "Creating On-Screen Rendering Surfaces":

    "On RISC OS, <win> is a Wimp window handle or
    EGL_RISCOS_SCREEN_WINDOW.

    By default, a surface for a Wimp window covers the window's visible
    area. It stays in place when the window's work area scrolls and follows
    the window's size: after the window is resized, the next
    eglSwapBuffers shows the finished frame at the old size, then resizes
    the surface for the next frame. Applications query EGL_WIDTH and
    EGL_HEIGHT to find the new size.

    If EGL_WORK_AREA_WIDTH_RISCOS and EGL_WORK_AREA_HEIGHT_RISCOS (in
    pixels, both greater than zero) are given, the surface instead has a
    fixed size and a fixed place in the window's work area: its top left
    corner is at EGL_WORK_AREA_X_RISCOS, EGL_WORK_AREA_Y_RISCOS (in OS
    units, work area coordinates, so Y is usually zero or negative; both
    default to 0). Such a surface scrolls with the work area, so a window
    can hold other content besides it, and a window can hold several such
    surfaces; later surfaces are drawn over earlier ones where they
    overlap. Giving only one of the width and height, a width or height of
    zero or less, or a width and height with EGL_RISCOS_SCREEN_WINDOW
    generates EGL_BAD_ATTRIBUTE. EGL_WORK_AREA_X_RISCOS and
    EGL_WORK_AREA_Y_RISCOS are ignored without a width and height.

    With EGL_RISCOS_SCREEN_WINDOW the surface is the whole screen, for
    full-screen, single-tasking programs. EGL_SCREEN_BANKS_RISCOS may be
    given as 0 (the default), 2 or 3; other values generate
    EGL_BAD_ATTRIBUTE, as does giving it for a Wimp window. With 0, rendering goes to an offscreen buffer that
    eglSwapBuffers copies to the screen. With 2 or 3, the implementation
    may render into hidden screen banks and show each on eglSwapBuffers;
    it may use fewer banks, or none, if screen memory does not allow them.
    Querying EGL_SCREEN_BANKS_RISCOS gives the number of banks in use (0
    for none, and for window surfaces). A surface using screen banks has
    EGL_SWAP_BEHAVIOR EGL_BUFFER_DESTROYED; setting EGL_BUFFER_PRESERVED
    stops using the banks. EGL_RENDER_BUFFER EGL_SINGLE_BUFFER renders
    straight into the visible screen."

    Add to section 3.10.3 "Posting Semantics", after eglSwapInterval:

    "On RISC OS, for a surface created with EGL_RISCOS_SCREEN_WINDOW,
    eglSwapBuffers waits for the given number of vertical syncs. For a
    surface in a Wimp window the swap interval is accepted and reported
    but does not delay eglSwapBuffers: waiting for vertical sync would
    stop every task on the desktop, which is cooperatively multitasked.
    Tasks pace their frames through their event loop (Wimp_PollIdle)
    instead."

    Add a new section 3.10.4 "Redrawing RISC OS Windows":

    "The implementation never calls Wimp_Poll: the calling task owns its
    event loop. eglSwapBuffers on a window surface updates the window
    immediately (through Wimp_UpdateWindow). When the Wimp asks the task
    to redraw a window (a Redraw_Window_Request event), the task calls

        EGLBoolean eglRedrawWindowRISCOS(EGLDisplay dpy, int *block);

    with <block> the Wimp_Poll block of the event (its first word is the
    window handle). The call runs the Wimp_RedrawWindow and
    Wimp_GetRectangle loop for that window and draws the last frame posted
    to every EGL window surface in it. <block> must be at least 44 bytes
    long, and its contents are changed as by Wimp_RedrawWindow.

    If the window has no EGL window surfaces, EGL_FALSE is returned, the
    error EGL_BAD_NATIVE_WINDOW is generated, and no redraw is started, so
    the task can run the loop itself. If <block> is NULL,
    EGL_BAD_PARAMETER is generated. If <dpy> is not a valid initialised
    display, EGL_BAD_DISPLAY or EGL_NOT_INITIALIZED is generated.

    A task that draws other things in the same window runs the redraw loop
    itself, and for each rectangle calls

        EGLBoolean eglPlotSurfaceRISCOS(EGLDisplay dpy,
                                        EGLSurface surface,
                                        const int *block);

    with <block> the block filled in by Wimp_RedrawWindow or
    Wimp_GetRectangle. The last frame posted to <surface> is drawn,
    clipped to the rectangle in words 7 to 10 of <block>. If <surface> is
    not a window surface for a Wimp window (a pbuffer, a pixmap, or the
    whole screen), EGL_BAD_SURFACE is generated. If <block> is NULL,
    EGL_BAD_PARAMETER is generated."

    Add to the description of EGL_NATIVE_VISUAL_ID in section 3.4:

    "On RISC OS the native visual ID is the colour order of the config's
    pixels, as the colour order bits of the ModeFlags mode variable:
    EGL_RISCOS_VISUAL_TBGR (0x00BBGGRR words, as sprite type 6) or
    EGL_RISCOS_VISUAL_TRGB (0x00RRGGBB words). Configs that match the
    current screen mode have the lowest EGL_CONFIG_IDs."

Issues

    1. Why doesn't the implementation redraw windows by itself?

       RESOLVED: on RISC OS, only the task that owns a window can respond to
       its redraw requests, and only from its own Wimp_Poll loop. A library
       cannot poll the Wimp on the task's behalf without taking over its
       event loop. The two functions let the task's existing loop do it.

    2. Why is the swap interval not honoured in windows?

       RESOLVED: the desktop is cooperatively multitasked; a task waiting
       for vertical sync inside eglSwapBuffers would stop all other tasks
       for that time. Full-screen programs own the machine, so there the
       interval is honoured. EGL 1.5 allows an implementation to clamp the
       interval; this extension makes the behaviour explicit instead.

    3. Why are work area positions in OS units but sizes in pixels?

       RESOLVED: Wimp work area coordinates are in OS units, which the task
       already uses to lay out its window; the surface size is the size of
       the GL framebuffer, which applications think of in pixels.
